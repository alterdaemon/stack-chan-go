# 2.0.1-r14

Release impact: patch.

CoreS3 realtime SPI now waits for idle/capacity events instead of actively yielding
in both producer and flush waits. The SPI worker updates level conditions under
the existing mutex; waiters recheck predicates after waking. The repository-owned
Moddable SPI source retains its LGPL notice and records its upstream identity.

An AEC-plane SRAM experiment is not retained: its isolated CPU benefit was small
and it consumed scarce internal-memory headroom. The final audio
implementation is byte-identical to the baseline source. WebRTC/Opus policy,
48 kHz hardware audio, pitch, 4/8 ms UI windows, services and saved settings retain
their previous behavior.

See [R14-PERFORMANCE-REPORT.md](../../R14-PERFORMANCE-REPORT.md) for measurements,
all proposal dispositions, exact validation outcomes and limitations. The normal release build, both image validations and normal device boot passed.
The post-test audit found a changed `tts.volume` entry (cause unknown); its
original value was restored through the Preferences API. All saved NVS value
groups match baseline after normal R14 boot. At the post-probe audit, bootloader/table/PHY/xs/storage bytes matched the
original backup. No raw NVS image was flashed.

Measured UI-only result: 4.388% median paired reduction in main+SPI CPU service,
13/15 positive pairs; no whole-device/audio-quality speedup is claimed. The
normal app is installed; both release images, evidence and limitations are in
the report. XS runtime checks requiring absent Xvfb, acoustic recordings and
the proposed long soak were not passed or claimed complete.
