# 2.0.1-r15

Release impact is patch. After the CoreS3 camera preview captures its frame,
the camera stops acquiring frames and releases the driver resources. The
preview renders from its copied frame and the next use opens the camera again.
A standalone `robot.camera.capture()` returns a copy and also closes the camera.
The runtime resumes touch after outstanding captures finish and the camera
releases the shared bus.

R14 sent a stop notification that the running capture task did not consume.
The two tasks used 11.755% of one core while active and 11.825% after stop.
The R15 worker checks notifications between frames and acknowledges shutdown
before the owner returns outstanding frames and deinitializes the Espressif
driver. [R14 camera measurements](../performance/r14-complete-device.json),
[Moddable binding and attribution](../../firmware/host/platforms/m5stackchan_cores3/camera/UPSTREAM.md)

## CoreS3 verification

| Check | Result |
| --- | --- |
| Camera task CPU after stop | R14 used 11.825% of one core. In R15 both `camera` and `cam_task` were absent after all eight stops, while the preview was still visible, after its dismissal, and after two overlapping standalone captures. |
| Memory released | At 160 × 120 RGB565, free internal memory rose by 29,972–30,604 B and free PSRAM by 115,436 B between active capture and 250 ms after stop. Free PSRAM returned to its pre-capture value in each cycle. |
| Reopen and stop | Eight starts returned a frame. The test closed the camera with one frame still leased, then released the frame. Immediate start/stop and repeated stop also finished with both camera tasks absent. Stop took 38.1–70.5 ms, median 56.3 ms. |
| Preview and standalone capture | The real drawer action rendered the bitmap and the runtime resumed the touch driver. Two overlapping standalone calls returned 38,400 B each that remained readable after driver teardown. |
| OpenAI after camera use | Both WebRTC modes started with voice interruption enabled. Over 3 s GPT-Live captured 50,176 and supplied 50,240 samples to the source path. GPT-Realtime Mini captured and supplied 48,640. Both had zero capture FIFO overruns and no camera tasks. The test used synthetic microphone input. Mini logged `hangup_failed` when closing the API session. |

The test covers short camera and audio lifecycle checks. Acoustic interruption,
physical touch latency and sustained provider stability remain unmeasured for
this patch. [Device measurements](../performance/r15-camera-device.json)

## Reproduction

From `firmware/` in the configured Moddable and ESP-IDF environment:

```sh
npm test
npm run test:providers
npm run lint
npm run format
npm run check:manifest
npm run check:release -- v2.0.1-r15
STACKCHAN_REALTIME_WEBRTC=1 npm run build -- --mode=release --manifest host/app/manifest_openai_camera_probe.json
npm run build -- --mode=release
```

`npm test` passed 618 unit tests, nine packaging tests and 11 RFID tests.
The three board provider tests passed. Lint, format, manifest preflight for
six targets and release validation passed.
The camera diagnostic used an app-only write at `0x10000` after checking the
connected device's partition table. It blocked writes to preferences and kept
temporary provider settings in RAM. Serial collection ran with `python3
firmware/scripts/capture-r14-complete.py --port <port> --startup 45 --seconds 155
--marker camera-probe --camera-events` from the repository root. The production
release uses the same camera binding and excludes the diagnostic modules.

## Installed application and data check

The normal build produced both R15 BINs. The application BIN matches the
build output and the application bytes at `0x10000` in the 16 MiB image. The
full image also matches the bootloader and partition table from the same build.
The R14 tag and both R14 images were verified against their recorded identities.

The robot received only the R15 application. Esptool verified the write and
the normal app reported `app behaviors ready` after reboot. All 458,752 bytes
read outside the application partition matched the pre-test readback, including
NVS, `xs` and storage. Temporary partition copies and decoded NVS dumps from
R14 and R15 were deleted after comparison. [Build and data audit](../performance/r15-camera-device.json)

To update the application on a device with the supported partition layout,
run this command from the repository root using the device's actual port.

```sh
esptool --chip esp32s3 --port /dev/ttyACM0 --baud 921600 --before default-reset --after hard-reset write-flash --flash-mode dio --flash-size 16MB --flash-freq 80m 0x10000 gpt-live-package/StackChan-Community-v2.0.1-r15-GPT-Live-app.bin
```
