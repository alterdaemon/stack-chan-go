# stackchan-community-mod 2.0.1-r11

Release impact: minor.

GPT-Live requests session closure after 60 seconds without microphone activity,
assistant playback or pending backend work. The existing LIVE button shows
STANDBY after cleanup. Tap it, or use the existing drawer action, to start a new
session. There is no automatic microphone wakeup in standby.

The existing close path sends `session.close`, waits for `session.closed`, then
releases the native transport. A 15-second finalization timeout still releases
local resources and reports ERROR instead of claiming a successful standby.
Native cleanup closes WebRTC, capture, playback, I2S, the AEC worker/handle and
Pitch. Host audio ownership and the low-latency radio lease are returned after
native shutdown, and the amplifier returns to 24 kHz.

The adapter retains only a transcript tail in RAM: at most 6 consecutive-speaker
fragments and 2048 text characters in total. Adjacent fragments from the same
speaker are joined; oldest text is evicted. The next session receives these
messages through `session.input`, with user/assistant roles preserved. No audio,
backend reasoning or tool results are retained. Explicit STOP, an error or a
device restart clears the tail. This is short text context, not restoration of
the old OpenAI session or its backend task state.

Inactivity polling runs once per second, only while connected. Native cumulative
input and audible-playback counters preserve brief activity between polls.
Input activity reuses the existing mean absolute PCM level after AEC/input
gating, with an energy threshold of 200 on PCM16 samples; muted capture does not
count. This is an energy gate, not semantic speech recognition: room noise may
delay standby. Missing/stalled capture statistics do not establish silence.
Transcript fragments also restart the interval; usage heartbeats do not.
Delegation creation and nested Responses lifecycle events block standby while
backend work is pending, including quiet reasoning and overlapping delegations.
The check can run up to one polling interval after the 60-second threshold;
STANDBY follows remote finalization and native cleanup.

Saved Voice, Pitch, Style, interruption and backend settings are read again on
resume. The R10 AEC priority fix and its non-blocking audio submission remain in
place; R11 adds no new DSP processor or audio task.

Protocol sources: OpenAI's [session lifecycle and startup history](https://developers.openai.com/api/docs/guides/live-conversations)
and [Live event reference](https://developers.openai.com/api/reference/resources/live/primary-websocket).

  matches both release-build copies and its range at `0x10000` in the full image.
  The full image matches the same build's bootloader/partition table, with all
  remaining bytes set to `0xFF`. Earlier revision images are retained.

Physical CoreS3 tests and live API conversations have not been run. Verify
